# 1장. korora의 목표와 전체 구조

예상 분량: 8쪽. 명령은 저장소 루트에서 실행합니다.

## 1-1. 측정 데이터가 저장되고 조회되기까지

클라이언트부터 진입점, 프록시, API, DB까지 전체 흐름을 읽고 쓰기와 조회를 다른 색으로 표시합니다.

[전체 구조도](../../README.md)를 바탕으로 이 장의 [kustomization.yaml](kustomization.yaml)에서 추가·변경된 연결을 표시합니다.

## 1-2. 서비스를 나누는 기준과 각 구성 요소의 책임

HTTP 서버·리버스 프록시·API·DB의 역할과 상태를 가진 구성 요소를 구분합니다.

## 1-3. korora의 데이터와 API 계약 정하기

측정 데이터와 쓰기·조회 요청을 작성하고 경로·메서드·필수 필드·응답을 정합니다.

~~~sh
cat chapters/01-overview/openapi.yaml
cat chapters/01-overview/sample-measurement.yaml
~~~

## 1-4. 정상 요청의 흐름을 따라가 보기

한 건을 저장하고 다시 조회하는 순서도와 각 단계에서 관찰할 결과를 작성합니다.

1장은 API 설계 실습입니다. openapi.yaml과 sample-measurement.yaml은 Kubernetes 배포 리소스가 아닙니다. kustomization.yaml의 배포 리소스는 비어 있습니다.

## 1-5. 구조도에서 연결 하나를 지워 보기

DB 연결이나 조회 경로가 빠진 그림에서 실패하는 기능과 이유를 설명합니다.

## 1-6. korora의 범위와 설계 원칙 기록하기

읽기·쓰기 API는 독립 배포하고 DB는 공유합니다. 공유 DB 장애의 영향도 기록합니다.
